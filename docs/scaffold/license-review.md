# Runtime component evidence

We examined the 35 non-main runtime components in the Linux/amd64 module graph
generated by cyclonedx-gomod v1.12.0. The complete BOM and dependency graph remain
in `bom.cdx.json`.

| Detected SPDX license | Components |
| --- | --- |
| Apache-2.0 | 18 |
| BSD-2-Clause | 1 |
| BSD-3-Clause | 9 |
| MIT | 6 |
| no detected evidence | 1 |

The 34 third-party components require detected SPDX evidence. The sole exact
first-party module, `github.com/zhangzhe-ctrl/ani-observability-service/api`
v0.1.1, has no declared open-source license. Its BOM evidence remains absent;
the service's all-rights-reserved statement and the upstream template notice
do not create an open-source license grant for the ANI API.

The provenance gate follows the existing Resource service workflow. It checks
the exact first-party identity, go.mod pin, both go.sum checksums, BOM checksum,
published module download and complete VCS Origin (including subdirectory and
commit) against `first-party-modules.json`. A different component or version
cannot inherit this classification. No fabricated SPDX or LicenseRef is added.
Every other component still requires nonempty SPDX license evidence.

`make audit` retains vulnerability and complete-history secret scanning,
deterministic complete SBOM generation, frozen upstream notice verification,
strict third-party license evidence and synchronization of these counts.
